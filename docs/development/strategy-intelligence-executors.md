# Strategy intelligence executors

The internal intelligence layer adds three exact `module_executor.v1` implementations.
It retains `ModuleExecutorRegistry -> ModuleExecutorDispatcher -> ModuleExecutionResult`
and the existing outer `QualityGateEvaluator` / `fully_accepted()` boundary. There is
no alternate quality mechanism, provider retry, persistence inside an executor or
production ingress. The integration base is merged PR #59, commit
`017bf09f11c3c0a16dde4e9b9c431e48064465fe`.

The immutable `EXECUTION_REGISTRY_VERSIONS` is exactly `{1.1.0, 1.2.0}`. Compiled plans
retain their exact version and fingerprint, including on PostgreSQL reload. A new
six-executor composition can execute a persisted 1.1 plan without upgrading it.
The compiler still compares descriptor metadata exactly with planning 1.0 after
removing availability/bindings. It does not accept arbitrary descriptor changes.
The runtime scenario allowlist is unchanged: `explicit_single_module_v1` and
`competitive_positioning_v1`. Neither `new_positioning_v1` nor Strategy Builder is
authorized by adding bindings.

## Explicit composition and input contracts

```python
executors = build_module_executor_registry(
    model_call=single_attempt_module_model,
    analyzer=competitor_site_analyzer,
    registry_version="1.2.0",
    market_analyzer=public_source_analyzer,  # optional, independent injection
)
metadata = ModuleRegistry.load("1.2.0")
```

No provider work happens at import or construction. The existing opt-in
`build_public_site_analyzer()` reuses cache-free UrlAnalyzer and safe HTTP fetching,
including public DNS/IP validation, redirects and byte/time limits. No new HTTP or
search stack is introduced. An absent model or required source capability returns
typed BLOCKED. Transport/model exceptions propagate once; malformed structured
output raises `ExecutorOutputError`. Retry policy remains caller-owned.

All facts are caller-authorized and module-scoped in the existing ContextPacket.
Typed PlanningInputKey values retain precedence over labels. The following additional
internal slots use exact fact labels; no public DTO or planning enum changes are needed.
Loose ContextPacket upstream findings are not a substitute for complete accepted
UpstreamExecutionResult objects. Callers must supply only fully accepted upstream
results, including ancestor closure for Quality Gates evaluation. Existing durable
reload enforces this; the runtime-neutral dispatcher does not perform evaluation.

### MARKET_ANALYSIS

Requires `product_or_category` and meaningful source/customer evidence. Geography
must be scoped by the caller where material. Evidence may be:

- Authorized first-party `existing_customers`, `internal_sales_data`, `current_segments`,
  `research`, or `customer_findings`. These remain FIRST_PARTY, not independent research.
- `market_sources`: a list of one to eight strict records containing `source_reference`
  (page/document reference, at most 2048 characters), `source_class` (EXTERNAL_PRIMARY
  or EXTERNAL_SECONDARY), and actual `excerpt` (at most 8000 characters). Source class
  is supplied by the authorized caller, never generated by the model.
- Accepted upstream results, reused via parent claim IDs rather than copied evidence.
- `market_source_urls`: one to three explicit public URLs. These require authorized
  SITE_FETCH and `market_analyzer`. URLs themselves are not evidence. Only nonempty
  fetched text becomes EXTERNAL_PRIMARY evidence of what that page says. For a known
  secondary research source, supply its excerpt with explicit secondary classification.

An unavailable URL capability blocks before the model call. Product/category alone,
failed/empty pages without other evidence, or invalid source records also block.
First-party-only research can produce PASS_WITH_LIMITATIONS, but no numerical market
size. There is no generic web search and no hidden use of model knowledge as evidence.

All claims cite local evidence or accepted parents. Observations must be verbatim
supported excerpts; other market conclusions remain hypotheses/recommendations.
Any statement containing digits must occur verbatim in its cited support. This
deliberately conservative first version does not calculate TAM/SAM/SOM or extrapolate
growth/share/statistics. Without external sizing support, `market_size_if_supported`
must be a nonnumerical hypothesis/unknown. Relevant research gaps remain explicit.

### VIRTUAL_CMO

Requires explicit `business_goal` plus `known_business_context` (the descriptor's
punctuated label `known_business_context.` is also accepted), `product`, or
`product_or_category`. Missing goal or decision object blocks before a model call.
It is a strategic synthesis expert, not MarketingCopilotService, an Orchestrator,
planner, scheduler or router. POSITIONING, MARKET_ANALYSIS and COMPETITOR_ANALYSIS
findings are supplied as accepted predecessor results.

Each requested output has one supported summary and one to three concise items.
`main_growth_constraint` has exactly one item and must be a HYPOTHESIS. All synthesis
is marked HYPOTHESIS/RECOMMENDATION. When parents exist, every synthesis output must
cite a parent; otherwise authorized first-party support is mandatory. Structured
items share that claim's support, assumptions and confidence ceiling and are included
in its normalized value. No ungated material list is appended to the payload.

Missing `economics`/`unit_economics` adds a deterministic limitation: profitability,
budget affordability and unit economics are unknown. Qualitative resource priorities
remain possible. No factual market/economic synthesis or invented numerical budgets
is allowed. Confidence cannot exceed the weakest cited parent or local support.

### EXPERIMENTS

Requires an accepted HYPOTHESIS claim from POSITIONING or VIRTUAL_CMO, otherwise
BLOCKED without a model call. The current claim contract has no claim materiality
flag: all output claims participate in full-result acceptance and are treated as
material. A recommendation alone, failed result or arbitrary other module does not
satisfy the hypothesis prerequisite.

One to three experiments contain hypothesis, target_metric, intervention,
expected_signal, failure_condition, minimum_required_inputs, time_resource_constraints
and related_strategic_claim_ids. Every experiment cites actual eligible hypothesis
parents. Every canonical output also cites an eligible parent. All supplied scoped
constraints and fact slots `constraints`, `time_resource_constraint`, `budget`,
`duration` must be preserved verbatim in each design's bounded constraint list.
Without supplied constraints the list is empty.

No new uplift, budget, duration, sample size or significance threshold is generated.
Numerical text in designs must quote its hypothesis parents verbatim; an explicitly
supplied numerical uplift hypothesis is allowed, without becoming a forecast.
Designs are normalized into the first output claim with the union of their parent
IDs and constraint evidence. Thus full-claim rejection prevents release of designs,
and the shared confidence clamp includes every experiment's parents.

## Strict payloads and limits

`MarketOutput`, `StrategyOutput`, and `ExperimentsOutput` are dedicated Pydantic
schemas in `intelligence_schemas.py`; result schema versions are respectively
`market_analysis.payload.v1`, `virtual_cmo.payload.v1`, `experiments.payload.v1`.
They forbid extra fields and bound every string/list. Every requested descriptor
output appears exactly once; canonical names, including terminal punctuation, are
preserved. The model only selects supplied references; code creates technical IDs.
The existing ExpertInstructionComposer supplies the shared core. All source,
context and predecessor text is untrusted data, and no hidden reasoning is requested.

Quality Gates remains a structural provenance/acceptance boundary, not a semantic
truth verifier. Verbatim support checks prevent novel digit-bearing statements,
but do not prove source truth, relevance or comprehensiveness. These executors
return limited results and require caller-provided evidence. They deliberately
do not supply autonomous research, numerical market modeling or formal sample-size
calculation. Excessive/unsupported structured output fails closed.

BUSINESS_DIAGNOSTICS remains metadata-only: its economics-first contract covers
CAC/CPL, LTV, profitability, break-even, payback and scaling economics. It is not a
generic own-site/product UX or positioning analyzer. That capability needs a
separate decision. No Strategy Builder graph, dynamic competitor expansion,
replanning, production Copilot ingress, Telegram/delivery changes or migration is
part of this change. Existing application composition stays on Registry 1.1.
