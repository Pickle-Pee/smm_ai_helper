# Case Mentor quantity grounding

Production acceptance of the saved workshop strategy exposed a separate dialogue
defect: Mentor restored the correct business/audience/city, then proposed an
unsupported `4–8` participant test population. The old structured response schema
checked shape but not numeric authority. Its instructions prohibited fabricated
financial results while allowing hypothetical allocation and omitting sample sizes.

New answers use qualitative advice by default. Sample sizes, durations, capacity,
thresholds, prices and budget splits cannot be invented even as examples. Supplied
product and fulfillment conditions must remain; an unspecified lesson does not
establish a one-off format. This instruction is guidance, not a semantic proof.

After parsing and before persisting an answer, the service checks each line in
paragraphs and unknowns with the existing finite RU/EN quantity detector. A line
with a quantity must occur verbatim and contiguously in an authorized field of the
actual bounded provider packet: supplied `inputs`, current/prior user questions,
user report notes/metrics, or server `feedback.analysis` JSON. Generated strategy,
prior assistant replies, run identifiers and window metadata grant no authority.
Hypothetical numeric allocations previously permitted by instructions are now
restricted to qualitative discussion; deterministic calculations can be quoted.
This intentionally rejects numeric paraphrases and newly calculated allocations.

List indices (`1.` or `1)` plus whitespace) and exact already-supplied ASCII
underscore-namespaced identifiers are ignored only for quantity detection.
Unknown IDs and tokens such as `6weeks` or `sample4to8` cannot bypass the check.
The original emitted line, after a structural prefix, is used for source matching.
No output is filtered, repaired, normalized or silently regenerated.

Before a new provider request, the same boundary checks full saved prior AI
answers. An answer that fails is omitted in its entirety from the provider-only
dialogue projection, with explicit omission/reason metadata and a history notice.
Its user question remains. The original answer is preserved and still displayed
in owner-scoped history/replay; no artifact is changed or deleted. This prevents
unsupported historical advice from repeatedly poisoning restored business facts.
Grounded prior answers retain the existing packet shape and bounded text window.
Historical validation recognizes the exact server-owned unknown-label prefix,
so a valid quoted unknown survives persistence/restoration. This exception is
validation-only for saved answers and does not authorize unsupported generated text.

A rejected generation follows the existing safe provider-error path: the durable
claim becomes unknown, no answer is saved/displayed, same-key replay after service
recreation cannot call the provider again. Public DTOs, deterministic explanations,
old saved answers, graph artifacts and PostgreSQL transaction ownership remain.
No migration or feature flag is required.

The check establishes literal quantity support, not semantic entailment. An excerpt
can omit a source qualification; user questions/reports remain unverified data.
The shared detector does not cover all compound words, languages or meanings.
A Mentor-specific finite rule also checks the RU adjective families разовый,
одноразовый, единоразовый, однократный and English one-off/one-time. Live checking
found reuse of an unsupported one-off lesson description from prior AI advice;
these operational counts now require the same literal source boundary. This is
not a general compound-word or fulfillment-condition parser. Prompt preservation and actual manual quality
review remain necessary. The service does not retroactively certify old answers.

Tests reproduce unsupported population, spelled counts and hypothetical spend
acceptance on the former implementation, then verify rejection before persistence.
They cover source exclusions, exact input/report/arithmetic excerpts, unknowns,
structural markers/IDs, no token-only number laundering, and real PostgreSQL
unknown/replay behavior without actual provider calls.
