# POSITIONING independent review: scoped_verdicts.v5

The immutable canonical draft remains server-owned. The verifier receives
closed server span IDs for each output. Their text and internal token ranges are
formed by the server; the auditor never counts inclusive/exclusive boundaries.
It never reproduces the draft or source quotes. A hash binds the report to the
exact draft, citations, evidence and contract version. No Unicode normalization
or UTF-16/byte offsets are used. The server resolves IDs into original text.

Reports are keyed by exactly the requested output names. Each output has its
own closed source-ID enum, limited to its existing citations and available
authorized sources. Complete source quotations are resolved by the server.
Anchors can overlap: several atomic propositions can occupy one sentence and
share an anchor. Sentence/clause segmentation is a selection aid, never proof
of atomic decomposition. The auditor still must identify all factual premises.
The union of ranges must cover every token. `atoms_complete` is a separate
semantic judgment; token coverage cannot prove extraction recall. The superseded
v2 numeric-range interface produced three end-boundary coverage failures on a
sixteen-output positive live sample. v3 removes numeric range calculation from
the model. Exact authorized prospective proposals do not depend on a correct
auditor category label; labels cannot make an unauthorized proposal eligible.

The v5 wire has only span_id, unit_id, verdict and support_ids per claim.
CLEAR is advisory: server-owned source roles and exact source/proposal contracts
still determine eligibility. The auditor cannot set kind/category/proof status.
Negative verdicts always survive server mapping. Original producer kind is a
quality hint, never proof. Per-output purposes explicitly permit a hypothetical
demand situation/customer job without observed research at WORKING depth.

Server-derived `audit_scope` separates an exact fully cited authorized prospective
proposal from source facts and arbitrary prose. For a bound proposal the factual
verdict is CLEAR, UNSUPPORTED or CONTRADICTED; empirical strategy validation is
explicitly REQUIRED and remains separate from factual fidelity. This does not
prove the proposed value, preference or distinction. Root UNCERTAIN, incomplete
atoms and unfulfilled output still veto acceptance. Source facts and free prose
retain UNVERIFIABLE. An out-of-scope verdict fails schema validation; it is never
translated to CLEAR. Removing a required citation, changing the proposal or
labeling an unknown property HYPOTHESIS cannot obtain prospective scope. The
saved v4 course with seven UNVERIFIABLE verdicts remains rejected. Its report did
not include reasons, so confusing untested value with factual uncertainty is an
inference from independently reviewed content, not known model rationale.

For closed recognized complete owner sources, source_fact_units() plans distinct
predicates with internal Unicode codepoint ranges. The server resolves anchors
and prescribes their evidence IDs. Every unit must appear exactly once with its
assigned anchor and source; duplicates or omissions fail even at full character
coverage. Materials and firing are separate units sharing a sentence. Collection
retains its full after-firing/another-day condition. Known source-plan coverage is
reported separately from model-reported atomic completeness. Unknown source
shapes have no such deterministic unit guarantee: an empty unit plan does not
prove semantic completeness. This is bounded typing, not general NLP extraction.


APPROVE cannot authorize arbitrary free prose by labeling it HYPOTHESIS.
Facts require the complete exact assertion from an eligible cited source;
demonstrations remain RTB-only. Nonfactual strategy uses a positive closed
prospective-language contract (`positioning_strategy.py`), supplied to generation.
Other wording fails closed, including valid paraphrases outside that contract.
When durable verification and support selection are enabled together, generation
uses `positioning.support_selection.v10`: each strategic output selects an opaque
request-scoped STRATEGY key. The server renders its exact proposal and binds all
required evidence IDs. Offer/RTB select complete SOURCE assertions. Free prose,
another output's key and unknown keys fail schema validation. The same catalogue
builder supplies generation and review; a model's harmless paraphrase cannot
accidentally disagree with the positive proof contract. The historical v9 wire
remains available while this rollout is disabled. No new public configuration
flag, canonical schema or migration is introduced.
Strategic selections permit only HYPOTHESIS/RECOMMENDATION, preventing a producer
from promoting a proposed demand, value or distinction to factual INFERENCE.
Production string identities enable request-scoped proposals for the actual
category, task, value, tentative difference and full positioning sentence. Exact
product/audience slots and each required source ID must match this request and
be cited. Feature-specific angles are enabled only by closed complete owner
source patterns; unknown prose enables a prospective generic angle, never a new
feature. Offer/RTB still carry complete exact source conditions. The
source-role taxonomy is extended with product identity, which is not proof of
product properties. Source roles are enforced by output independently of labels.

Explicit photography-course and ceramics-masterclass identities, a single
audience and matching complete owner truth enable purpose-specific profiles.
These supply actual category/comparison/value/message/risk proposals rather
than generic research tasks. Each profile proposal binds all three source IDs;
the course preserves practical tasks/written feedback, while ceramics preserves
materials/firing and collection on another day. A complete authorized proposal
can contain several separately reviewed recommendations. Partial anchors cannot
remove its qualifiers. Demonstration citations outside RTB are rejected even
when the auditor ignores their lack of relevance.

This restriction can reject useful strategy. Relevance, section purpose and
usefulness remain independent acceptance criteria; template membership is not
proof of production quality. `output_fulfilled` must be true for every output in
addition to `atoms_complete`. A safe research task that fails to supply the named
positioning output must block acceptance. Numeric/overlong identity slots cannot
be interpolated into mixed strategy; existing numeric guards remain unchanged.

Known factual-premise detectors provide additional diagnostics and scan the
whole row to prevent splitting a risky phrase across atoms. Their negative
result never grants approval. An independent review reproduced an arbitrary
accreditation claim passing the earlier negative-word-list approach; the positive
strategy contract closes that class of bypass.

`verification_inputs()` reconstructs evidence using the executor's identities.
Evidence-backed factual competitor/market parents may be cited only by their
existing parent claim ID. Hypotheses and parents with missing evidence records
are excluded. No new competitor source or product property is inferred.

Fulfillment is tri-state: `requires_follow_up=True` is established only by a
closed complete owner-source pattern for delayed collection, optionally with
the exact materials/firing prefix. Ambiguous/legacy prose yields `None`, never
False. `fulfillment_guarantee=unavailable` explicitly records that limit.
Known no-further-action promises are checked on the complete draft independently
of auditor labels. This is a bounded invariant, not general source entailment.

Persistence tables and canonical result schemas do not change. Existing accepted
artifacts retain their historical semantics. Old in-flight responses cannot be
replayed across changed generator/verifier instructions, evidence or schemas:
the existing payload/draft hash mismatch blocks recovery without another POST.
Same-revision recovery replays saved text/receipt, including the independent
review, without repeating either successful call. Unknown outcomes remain
terminal and cannot be reclassified as successful or free.

For new acceptance runs, process-local HTTP timeout 120s is valid with the
existing graph wall deadline 300s and lease 330s. Both generation and verification
share the graph's absolute deadline. HTTP timeouts cover transport inactivity,
not a guaranteed 120s wall allocation. Defaults and rollout flags stay unchanged.

## Downstream fidelity boundary

Full strategy acceptance exposed two defects after a verified POSITIONING:
EXPERIMENTS converted a tentative next-practice value into customer copy saying
"получите понятное направление", and CMO described an existing demonstration
without selecting its evidence. QG acceptance alone did not establish semantic
fidelity. The saved full course remains a semantic FAIL, not a repaired PASS.

`downstream_fidelity.py` is a shared, bounded canonical check for CMO and
EXPERIMENTS. It visits statement text, every CMO item, every nested design string,
assumptions and limitations before result/artifact persistence. Recognized direct
customer-outcome copy requires a complete verbatim selected request-local
product_truth/confirmed_business_fact as that leaf (with only closed quotation
wrappers). Appending a valid source elsewhere cannot authorize a new outcome.
Demonstrations, audience sources and generic accepted HYPOTHESIS parents never
become owner proof. Exact attributed evidence-backed competitor facts remain
foreign quotations, never proof of our product. Control/treatment also reject
recognized third-person product outcome copy without that owner witness.

An assertion about what an existing demo shows must reproduce the complete
selected existing_proof in its own leaf. Keep tentative interpretation or planned
use in another item. New material preparation without an existing-proof assertion
is allowed; assertive demo-relative clauses have only closed comparison/question
exceptions. A generic 'create/check/hypothesis' prefix cannot hide a current fact.

Explicit customer learning goals, bounded operator research-result statements
and whole counterfactual warnings remain allowed. These lexical Ru/En guards are
not a general NLP entailment/extraction system. Unrecognized arbitrary prose is
not thereby proven safe; supported paraphrases outside the closed copy contract
can reject. Independent actual-content acceptance remains separate. Existing
number guards and source-role limits are not weakened.

No persisted schema or migration changes. Historical accepted artifacts retain
their historical semantics, including saved diagnostic failures. New generation
is stricter; a post-response semantic failure does not authorize another POST.

Global negative evidence limitations have a separate bounded context check.
Whole closed RU/EN clauses stating that a supplied demonstration does not prove
effectiveness are permitted only when request-local FIRST_PARTY existing_proof
positively witnesses an actual demonstration. A keyword in an absent, planned,
conditional or unrelated source cannot confer this authority. This is metadata
about a proof limitation, not permission to assert product outcomes or what the
demo positively shows. Assumptions, statement text/items and nested designs
retain the existing source checks; appending a promise or positive assertion to
the negative clause does not match the limitation grammar. Other safe free-form
limitations outside this bounded grammar can still reject.

EXPERIMENTS support-selection v4 constrains only `evidence_basis` to a closed
RU/EN provenance note: the explicitly selected accepted strategic hypothesis
guides a test and does not establish effectiveness. It cannot generate a mixed
demo-proof assertion there. The source IDs, array shape, canonical payload and
all fifteen other output contracts remain unchanged.

Two bounded nonassertive RU verb contexts no longer trigger the current-demo
check through whole-leaf keyword co-occurrence: operator-clause-head
`дополнительно показывать`, and conditional test/interview subjects such as
`если качественные интервью и тест показывают`. Only the individual verb match
is excluded, outside quoted/public-copy leaves. Another positive assertion or
relative demo clause still triggers the original whole-source guard. Product
or participant future predicates containing the same infinitive do not qualify
as an operator clause. This is not a general grammatical/entailment classifier.

Recognized personal/individual feedback or review, and assertions that written
feedback shows/contains particular changes or content, require a complete
verbatim selected request-local owner source. A demonstration comparison,
audience wish or accepted parent HYPOTHESIS cannot establish these delivery
properties. The check also visits nested designs and global fields before
persistence. Closed whole audience research questions, goals/preferences and
negative policy warnings remain usable; appending an owner quote cannot repair
an unsupported feature elsewhere in the leaf. Unknown properties such as
regularity/systematic practice remain outside these bounded runtime families
and require separate actual-content review. The instruction also explicitly
treats upstream risk warnings as constraints, not a product-feature catalog.

## CMO qualitative generation and spelled quantities

The d9ddd25 full-course diagnostic reached a verified POSITIONING artifact, then
failed CMO on an unsupported "два варианта". The existing canonical quantity
guard correctly rejected it; the provider's ASCII-digit-only pattern had not
prevented it. CMO support-selection wire v5 additionally excludes the observed
count forms two/два/две/двух/двум/двумя in qualitative text/items. The complete
canonical guard remains authoritative for all other counts. Numeric context
still permits complete request-scoped source quotes,
including quantities spelled as words. Canonical quantity/provenance validation,
persisted DTOs and durable operation IDs are unchanged. EXPERIMENTS/POSITIONING
generation schemas are unaffected by this CMO-specific constraint.

The small regular pattern uses a trie complement with explicit RU/EN case
pairs/boundaries and anchors only outside the expression. The prior lookahead
candidate and a repeated inner-end-anchor variant both yielded empty incomplete
responses. A differential matrix isolated the anchor construction; the final
full-vocabulary pattern completed a primitive probe but truncated the actual
CMO response. Provider causation is unknown; this motivated the small filter
instead of treating a primitive pass as full-schema acceptance. Harmless "one
of the options" remains allowed. Other counts/languages, Unicode digits and
arbitrary semantic quantities remain
the canonical guard's responsibility. It is not a complete quantity ontology.
An existing operation with a saved response or changed fingerprint cannot be
resubmitted merely because the wire version changed.
