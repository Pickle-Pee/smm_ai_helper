# Strategy uncertainty and request-constraint presentation

## Observed gap and existing authority

A technically accepted strategy could display causal-looking CMO prose without
its existing HYPOTHESIS/RECOMMENDATION meaning. Canonical CMO models already
restrict these kinds; the main growth constraint is always HYPOTHESIS. Public
StrategySection carries text/items/numeric_context, without kind or confidence.
The renderer must not guess a per-section kind or alter saved model text.

The experiment constraint list also carries more than time or resources.
MarketingIntent.constraints and ContextPacket.constraints are general request
restrictions. The planner preserves them, and experiment_constraint_evidence
selects all scoped constraints plus explicit constraint/budget/duration slots.
The executor requires exact set equality in each design. Generic instructions
and business-scope isolation conditions are therefore legal constraint values.
Calling the whole list time/resources misrepresented the existing contract.
Read-only final7A evidence confirmed both general instructions in its compiled
plan and exact equality with all three experiment design lists. No content
filtering or new classification is needed for this display defect.

## Narrow presentation change

When a public run contains a strategy, its existing first readiness message adds
one notice: strategic conclusions are working hypotheses/recommendations, and
demand, refusal causes and channel effectiveness require checking. The notice is
part of that first message, not a new message or a guessed per-section label.
All nine section titles/order, model prose, items and numerical context remain
unchanged. Runs without a strategy do not receive the notice. The notice does
not prove source truth or make an unsupported causal statement valid; qualitative
review and two clean final workflows remain separate acceptance requirements.

Telegram labels experiment time_resource_constraints as request constraints.
New deterministic Mentor explanations use the same neutral meaning in each
constraint prefix and the missing-economics fallback. Both generic instructions
and actual budget/time limits are preserved verbatim; nothing is filtered,
classified from keywords or promoted to a resource fact.

The historical field name time_resource_constraints stays unchanged. No DTO,
provider schema, model instruction, selector, decoder, support/number/constraint
guard, Quality Gate or persistence contract changes. No database migration or
artifact rewrite is required. Already saved Mentor explanations replay their
original stored paragraphs; this change applies to newly generated explanations.
Telegram run rendering uses the new labels when existing or new runs are read.

## Regression evidence

New tests first reproduced all three display defects. They cover the first-message
notice, its absence for non-strategy results, all nine sections with exact text,
items/numerical context and order, mixed general/resource constraints, unchanged
public DTO values, original executor/Quality Gates acceptance of those supplied
constraints, neutral Mentor labels/fallback and unmodified accepted artifacts.
Adjacent Telegram and Mentor suites cover splitting, markup and saved-case flows.
Offline tests do not establish provider quality or production acceptance.
