# POSITIONING assurance acceptance and provider syntax

The finite canonical product-assurance detector is preserved unchanged in
positioning_assurance.py and remains authoritative for every output and kind.
A generated qualification or guarantee must quote the whole actually cited local
product_truth/existing_proof assertion. Other categories, uncited proof and
accepted parents do not establish product authority. There is no text repair,
qualification removal, source inference or automatic replacement generation.

Producer instructions require unqualified roles and prohibit added assurances in
all sections, including competitive frame and message hierarchy. The v4 provider
wire chooses QUALITATIVE prose or an entire literal SOURCE assertion explicitly.
Both modes pass the existing canonical checks after decoding; SOURCE is not a
citation. Public canonical strings and historic readers retain their contracts.

The former positive word grammar is removed from generation. Larger finite-word
patterns passed small API compatibility examples but repeatedly stopped early in
full restored contexts, including below the configured token limit. This does
not establish the provider's internal cause. The current producer reuses the
existing portable ASCII-digit-free assertion pattern, while canonical assurance
checks remain unchanged; the shared numeric modifier list additionally recognizes
introductory/вводный (see positioning-word-quantity-provider-contract.md). Free syntax can admit a bad
assertion; the actual executor rejects it before artifact persistence and QG.

Tests prove this boundary with syntactically valid generated qualifications that
fail actual executor validation, exact sourced qualifications without punctuation,
unrelated-category/uncited-source rejection, no implicit citation and unchanged
raw responses. Existing canonical assurance-family regressions still apply.
See positioning-tagged-text-wire.md and the incident progress log for live evidence.
