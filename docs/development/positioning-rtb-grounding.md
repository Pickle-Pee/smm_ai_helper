# POSITIONING reasons-to-believe boundary

Manual Telegram review of a technically accepted workshop strategy found an
unsupported RTB conclusion: included materials/firing were presented as proof of
an experience requiring no further customer actions. The supplied product facts
only established classes with a master, included materials/firing and collection
after firing. A valid product evidence ID alone did not support the added promise.

For newly generated `RTB`, require the whole statement text as a literal contiguous
quotation from one actually cited local `product_truth` or `existing_proof` source.
Another local category, an uncited matching source or an accepted parent cannot
authorize it. Keep existing product-source minimum and numerical checks first;
unsupported qualitative RTB then fails with bounded `rtb_quote_required` metadata.
Do not rewrite, repair, silently retry or persist an invalid model statement.
Instructions ask for actual supplied substantiation instead of a new conclusion.

This output-specific constraint leaves creative positioning/offer hypotheses and
recommendations available in their existing sections. Canonical kinds, DTOs,
provider schema/wire flags, source/claim IDs, bounds, confidence caps and Quality
Gates remain. No migration. Old stored artifacts remain readable and unchanged;
they are not retroactively certified by this stricter generation check.

The literal boundary establishes source presence, not independent factual truth
or general semantic entailment. A quotation can omit a qualifier; supplied owner
claims remain unverified, and overall manual quality review remains necessary.
This does not convert every positioning section into an extractive quotation.

Regressions reproduce the unsupported product-promise class on the former code,
then cover exact cited product/proof support, uncited/other-category/parent
laundering, rule precedence, other-output compatibility and old payload reading.
Shared provider doubles now generate a literal RTB initially; mutation hooks still
inject invalid output for rejection tests. Current runtime instruction golden is
updated from actual capture, preserving historical incident measurements.
